## 🚀 优化 1: FFmpeg 多线程优化

### 问题
- FFmpeg 默认可能不会充分利用多核 CPU
- 没有显式设置线程数，可能导致单核瓶颈

### 优化方案
- **添加 `-threads 0` 参数**：让 FFmpeg 自动检测 CPU 核心数并选择最优线程数
- **适用场景**：
  - WebRTC 编码：`-threads 0`
  - HTTP-FLV/HLS 编码：`-threads 0`

### 效果
- ✅ 充分利用多核 CPU（检测到 14 核，会自动使用）
- ✅ 提升编码性能（多核并行编码）
- ✅ 支持更高并发流数

### 代码位置
- `src/utils/ffmpeg_params.cpp`:
  - `AddWebRTCEncodingParams`: 第 46 行
  - `AddStreamingEncodingParams`: 第 104 行

## 🚀 优化 2: 码率控制优化

### 问题
- 码率控制参数可能不够优化
- 缓冲区大小可能影响编码稳定性

### 优化方案
- **优化缓冲区大小计算**：明确设置为码率的 2 倍
- **使用 ABR（平均码率）模式**：在保持平均码率的同时允许小幅波动，提升画质
- **添加详细注释**：说明参数的作用和选择原因

### 效果
- ✅ 编码稳定性提升（足够的缓冲区）
- ✅ 画质提升（ABR 模式允许小幅波动）
- ✅ 延迟保持（2 倍码率缓冲区是实时流的良好平衡）

### 代码位置
- `src/utils/ffmpeg_params.cpp`:
  - `AddVideoBitrateParams`: 第 6-20 行

## 🚀 优化 3: ZLM 网络参数优化

### 3.1 UDP 接收缓冲区优化

**问题**：
- 默认 UDP 接收缓冲区可能不够大
- 高码率流或高并发场景可能丢包

**优化方案**：
- **增加 UDP 接收缓冲区**：从 4MB 增加到 8MB
- **位置**：`configs/zlm_config.ini` → `[rtp_proxy]` → `udp_recv_socket_buffer`

**效果**：
- ✅ 减少 UDP 丢包（更大的缓冲区）
- ✅ 提升高码率流稳定性
- ✅ 支持更高并发

### 3.2 HTTP 发送缓冲区优化

**问题**：
- HTTP 发送缓冲区可能不够大
- 高码率流发送时可能频繁系统调用

**优化方案**：
- **增加 HTTP 发送缓冲区**：从 64KB 增加到 128KB
- **位置**：`configs/zlm_config.ini` → `[http]` → `sendBufSize`

**效果**：
- ✅ 减少系统调用（更大的缓冲区）
- ✅ 提升 HTTP-FLV/HLS 流发送效率
- ✅ 降低 CPU 使用率

### 3.3 RTP 参数注释优化

**优化方案**：
- 添加详细的 RTP 参数注释
- 说明参数的作用和调优建议

## 🔧 技术细节

### FFmpeg 线程数设置

```cpp
// 自动检测 CPU 核心数
oss << " -threads 0";  // 0 = 自动检测
```

**说明**：
- `-threads 0`：FFmpeg 会自动检测 CPU 核心数并选择最优线程数
- 对于 14 核 CPU，FFmpeg 会自动使用多个线程并行编码
- 每个核心通常可以处理 1-2 路 1080p@30fps 流

### 码率控制参数

```cpp
int bufsize = bitrate_kbps * 2;  // 2 倍码率作为缓冲区大小
oss << " -b:v " << bitrate_kbps << "k"
    << " -maxrate " << bitrate_kbps << "k"
    << " -bufsize " << bufsize << "k";
```

**说明**：
- `bufsize = 2 * bitrate`：提供足够的缓冲空间
- 对于实时流，2 倍码率是延迟和稳定性的良好平衡
- 使用 ABR（平均码率）模式，允许小幅波动以提升画质

### ZLM 网络缓冲区

```ini
[rtp_proxy]
udp_recv_socket_buffer=8388608  # 8MB（从 4MB 增加）

[http]
sendBufSize=131072  # 128KB（从 64KB 增加）
```

**说明**：
- UDP 缓冲区：8MB 可以更好地处理高码率流和突发流量
- HTTP 缓冲区：128KB 可以减少系统调用，提升发送效率

## ⚠️ 注意事项

### 1. 线程数设置
- **自动检测**：`-threads 0` 是最佳选择
- **手动设置**：如果需要，可以显式设置（例如：`-threads 4`）
- **注意**：过多的线程可能导致上下文切换开销

### 2. 缓冲区大小
- **UDP 缓冲区**：8MB 对于大多数场景足够，但要注意系统限制
- **HTTP 缓冲区**：128KB 是合理的，不会占用太多内存

### 3. 系统资源
- **内存**：更大的缓冲区会占用更多内存
- **CPU**：多线程编码会充分利用 CPU，注意系统负载
